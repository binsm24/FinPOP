# 게임·문항 DB 로컬 검증 결과

## DB·문항·서버 검증

- 게임 테이블 7개와 문항 테이블 5개의 생성·외래키·검사 제약·유일 인덱스.
- 게임 공개 테이블 5개의 본인 조회·타인 비노출.
- 익명 조회와 앱 직접 생성·잔액 변경·삭제 차단.
- 문항 카탈로그 전체·비공개 정답·중복 요청 기록의 앱 직접 조회 차단.
- 활성 게임·열린 차례·요청 키 중복 차단.
- 게임·참가자·차례 참조 일치와 잘못된 위치·특수칸 소유 차단.
- 4개 보기의 ID 유일성·본문, 유효한 정답, 승인 전 정답·출처 확인.
- DRAFT 편집 허용, APPROVED·RETIRED 내용·정답·출처 연결 변경 차단.
- 원본당 승인 버전 1개와 폐기 버전 재승인 차단.
- 다른 버전이어도 같은 게임의 원본 문항 재출제 차단.
- 새 버전 승인 후 과거 출제 문제·정답·해설·출처 사본 보존.
- 실제 RPC 생성·선공·이동, 치즈 보너스·출발 보상·20초 퀴즈 발급.
- 요청 재시도 동일 응답·충돌 처리, 문항 고갈·미구현 능력·이벤트 시 변경 롤백.

최초 기본 스키마 검증에서 발견한 현재 참가자·차례 불일치는 복합 외래키로 보강했습니다.
문항 정규화 후 같은 원본의 다른 버전 중복도 외래키·유일 제약과 서버 선택 로직으로 차단했습니다.

## HTTP 검증

사용자 JWT 누락·Auth 거절, 본문 ID 위조·주사위 주입·잘못된 버전·키·본문 크기 차단.
검증된 사용자 ID와 키의 RPC 전달, 충돌 응답 보존, 통신 장애 처리와 내부 오류 비노출.
Auth·PostgREST 네트워크 응답은 테스트에서 모사했습니다.

## 재실행

Node.js와 npm이 설치된 환경에서:
cd tools/db-schema
npm install
npm test

이 테스트는 메모리 DB에만 SQL을 적용합니다. Supabase URL·키·비밀번호를 사용하지 않습니다.
DB 상세 결과는 실행 폴더의 results.json에 생성되며 Git에는 포함하지 않습니다.
quiz-fixture.sql·rpc-quiz-fixture.sql은 로컬 테스트 전용으로 운영 문항이 아닙니다.

## 한계

순차 테스트이므로 실제 다중 연결의 경쟁·교착과 잠금 동작은 별도 검증해야 합니다.
